# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Graduation project: an AI-assisted medication tracking and family notification system for elderly users, built with React Native (Expo SDK 58, TypeScript), Supabase, and Expo Notifications. `README.md` is written in Turkish and lists the planned features.

Sprint 1 (issues #1–#4) is implemented; see `docs/sprint1-plan.md` for its decisions and risks. The code was then refactored into a layered, OOP structure; see `docs/moduler-yapi.md` and decision 2 in `docs/kararlar.md`. Data lives on the device in AsyncStorage. Supabase is not connected yet and `supabase/` is empty.

## Commands

The repo has no root `package.json`, so run all of these from `app/`:

```bash
npx expo start              # dev server (i / a / w to open iOS, Android, web)
npm run kontrol             # typecheck + ESLint/Prettier + Jest (run after every change)
npm test                    # Jest with coverage report (coverage/)
npx tsc --noEmit            # typecheck only
npx expo install <package>  # add dependencies with SDK-compatible versions
npx expo-doctor             # diagnose dependency and config issues
```

- `expo-env.d.ts` is gitignored and generated by `expo start`. On a fresh clone, `tsc` reports missing CSS module types until the dev server has run once.
- Tests use Jest with the `jest-expo` preset and live in `__tests__/` folders next to the code. Never put test files under `src/app/`, because Expo Router would treat them as routes.
- ESLint (`eslint.config.js`) and Prettier (`.prettierrc.json`) are configured; `npm run format` fixes formatting.
- CI (`.github/workflows/kontrol.yml`) runs typecheck, lint, and tests on every push and PR.
- `tsc` also needs the typed routes that `expo start` generates, so restart the dev server once after adding a route.
- Notifications, the camera, and haptics can only be verified on a real phone.

`app/AGENTS.md` holds the Expo rules: check versioned docs rather than relying on memory, and never hand-edit generated `ios/` or `android/` folders.

## Architecture

Layers, from top to bottom: screens (`src/app/`) → hooks (`src/hooks/`) → state (`src/context/`) → services (`src/services/`) → models, validation, utils, errors.

- **Routing:** Expo Router with its root at `app/src/app/` (not `app/app/`), using a single `Stack`: `index` (today's doses), `ilac-ekle` (add medication), `aldim/[id]` (full-screen confirmation, with `time` and `date` params). Typed routes and the React Compiler are enabled in `app.json`. The root layout wraps everything in `ErrorBoundary`.
- **Services:** Classes in `src/services/` hold all business logic and receive their dependencies through the constructor. Real instances are wired in one place, `src/services/index.ts`. Services are stateless: they take the current list, save, and return the new list.
- **Screens reach services only through hooks:** files in `src/app/` and `src/components/` never import `@/services` or `expo-notifications`; add a hook in `src/hooks/` instead.
- **State:** `src/context/medications.tsx` only holds React state and calls services. It holds splash-screen readiness through `isLoaded`, so the root layout must keep rendering the `Stack` while loading. Screens reach it through `useMedications` in `src/hooks/`.
- **Storage:** `IStorage` in `src/services/StorageService.ts`, implemented by `AsyncStorageService`. The keys `medications` and `doseLogs` and their JSON field names must never change. `schemaVersion` holds the data version, and `src/services/migrations.ts` upgrades old data. Corrupt data is copied to a `<key>.yedek-<timestamp>` key and never overwritten.
- **Dose status is derived, not stored:** only taken doses are saved as `DoseLog`. `DoseService.getTodayDoses` computes pending and missed from the clock (missed after 30 minutes). `DoseService.doseLogId` is deterministic, which prevents a dose from being confirmed, or stock from dropping, twice.
- **Medication forms:** `src/models/forms/` has the abstract `MedicationForm` and `Tablet`, `Syrup`, `Drops`, `Cream`. Resolve one with `getMedicationForm(medication.form)` and call its methods (`confirmLabel()`, `stockAfterDose()`) instead of branching on the kind. A missing or unknown form counts as Tablet.
- **Notifications:** `NotificationService` schedules local daily notifications with the ID `${medicationId}-${time}`. `sync` reconciles them with stored data on launch and leaves `test-*` IDs alone. `subscribeToDoseTaps` turns taps into a `DoseTarget`, including the last tap from a closed app, and ignores a repeated tap; the root layout navigates through the `useDoseNotificationTaps` hook once data has loaded.
- **Platform differences:** `notification.date` is in seconds on iOS and milliseconds on Android, so always read it through `NotificationService.normalizeDate`.
- **Photos:** `Medication.photoFile` stores a file name, not a path, because the iOS app container path can change. Resolve it with the `useMedicationPhoto` hook.
- **Errors and logging:** Throw `AppError` subclasses from `src/errors/`; show `userMessageOf(error, fallback)` to users. Log through `logger` in `src/utils/logger.ts`, never `console` directly.
- **Config:** Environment variables are read only in `src/config.ts`. The Claude API key never enters the app.
- **Theming:** `src/constants/theme.ts` is the single high-contrast light theme and holds the minimum font and button sizes.
- **Platforms:** iOS and Android only; web is not a target.
- **Imports:** `@/*` maps to `src/*`, and `@/assets/*` maps to `assets/*`.
